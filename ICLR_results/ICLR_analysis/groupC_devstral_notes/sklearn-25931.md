# sklearn-25931 (IsolationForest fit warns "X does not have valid feature names" when contamination != "auto") — Devstral-24B, ICLR main

Scope: ICLR_results/swebench/main/devstral24b only. 39 runs: FC 3/3 resolved; compressed 20/36 resolved (16 fail: 9 wrong patch submitted, 6 step-limit, 1 crash).

## Gold fix & hidden constraints
- Gold: add `_score_samples(X)` (no validation) and call it from `fit()` instead of `score_samples(X)`; `score_samples` keeps `_validate_data(..., reset=False)` then delegates.
- Mechanism the agent must reconstruct: `fit()` rebinds `X = self._validate_data(X, accept_sparse=["csc"], dtype=tree_dtype)` (line 291) so X is an ndarray by line 348; `score_samples` then runs `_validate_data(ndarray, reset=False)` → `_check_feature_names` warns. `score_samples` returns `-self._compute_chunked_score_samples(X)` (line 440).
- Hidden test constraints: (1) F2P turns UserWarning into an error → any variant that still calls `_validate_data(reset=False)` on the ndarray fails. (2) P2P `test_iforest_works[42-0.25]` etc. → `offset_` must be the percentile of the *negated* chunked scores (sign matters). (3) P2P `test_iforest_chunks_works1/2[42-0.25-3]` mock `get_chunk_n_rows` and assert `call_count == 3` with contamination=0.25 → fit must still go through `_compute_chunked_score_samples`.
- Resolving variants seen: (A) `score_samples(X_original)` (pass the pre-validation DataFrame), (B) `-self._compute_chunked_score_samples(X)`, plus hacks (delattr `feature_names_in_`, `reset=True`, base.py kwarg). Wrong-but-plausible variants invited by the PR text ("calls predict on the training data"): convert X with `.values`/`np.asarray` (X is already an ndarray → no-op or AttributeError), re-validate with `reset=False` (that call *is* the warning), drop the minus sign, call unchunked `_compute_score_samples` (breaks constraint 3).

## Root cause
Because the container's default interpreter (3.11) cannot import the 3.9-built extensions and no run finds the `testbed` env, this task is a pure code-reading edit: the agent must hold three facts at once — fit rebinds X to an ndarray (line 291), `score_samples` returns the negated chunked scores (line 440), and `_validate_data(reset=False)` is itself the warning source — and pick variant A or B without ever running a test. FC keeps all three reads plus its own doubt trail in context through submission, which is exactly what let FC/r3 catch its own dropped minus sign at step 57. Compression policies fail here not by inducing the wrong edit (5/6 wrong non-OTRC edits pre-date the compression event) but by converting the edit into a summarized "fix applied successfully" fact or clearing the reads behind it, after which the agent stops re-deriving and submits (ss/r1, trc-ss/r2, su-full/r3, su-partial/r3), by garbling the ndarray fact so the post-summary agent re-inserts the warning call (su-partial/r1), or, under online clearing, by erasing the memory of failed build attempts so a correct on-disk patch is never submitted (otrc/r1, ss/r3). The OTRC-family `.values` no-ops reflect never reading line 291 at all; the remaining failures are the msg[1] harness bug (3 runs), one degenerate-output crash, and one hidden chunk-count test.
