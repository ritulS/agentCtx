## Gold fix & hidden constraints
- 5 hunks in `sklearn/impute/_iterative.py`: docstring; `"fill_value": "no_validation"` in `_parameter_constraints`; `fill_value=None` kwarg in `__init__`; `self.fill_value = fill_value`; pass `fill_value=self.fill_value` to `SimpleImputer(...)` in `_initial_imputation`.
- F2P test: `IterativeImputer(missing_values=-1, initial_strategy="constant", fill_value=100, max_iter=0).fit_transform(X)`, asserts `initial_imputer_.statistics_ == 100`. Hidden constraints: (1) param must be a keyword named `fill_value`; (2) `fit` runs `_validate_params()`, so any `_parameter_constraints["fill_value"]` entry must be valid — the literal `"no_validation"`, or a list of None/types/`Interval`/`StrOptions`/known strings. Invented strings (`"numeric"`, `"string"`) raise `ValueError: Unknown constraint type` at fit (checked with `make_constraint` in venv sklearn 1.7.2); omitting the entry is fine (validator skips unconstrained params — FC r1/r3 resolved without it). (3) validation code placed in `__init__` before the attribute assignments -> AttributeError. Hint text ("pass a SimpleImputer instance as initial_strategy") was not followed by any run.
- Plausible-but-wrong variants observed: invented constraint strings (5 runs), `fill_value=fill_value` passed to `super().__init__()` (TypeError), validation in `__init__`, sed/regex edits that delete or corrupt neighbouring lines.

## Mechanisms with evidence
1. Constraint-vocabulary evidence is early and needed late. The only in-repo example of a free-form constraint is `"fill_value": "no_validation"` in `_base.py` SimpleImputer, read at steps 3-7. Every run that wrote `"no_validation"` had that line in context when it wrote it (fc r2: seen 3, written 23; su-partial r1: seen 9, written 18). Runs that wrote `"numeric"`/`"string"` either never viewed that section (su-full r2 step 28, trc-su r3 step 20, otrc-tr r1 step 16) or had it cleared by OTRC (otrc-tr r2: seen 6, written 29; otrc-su-partial r3: seen 3-4, written 14). 0/16 resolved compressed runs used an invented string; 5/11 unresolved submissions did. Nothing can execute, so the error is never observed.
2. Summaries assert completion and hide defects. su-full r1 summary (msg2, comp 53): "Made source code modifications... Validation Logic... Modified SimpleImputer" — no mention that step 42's `625,630c` removed `X_filled`; the post-comp diff at 76 prints the `-X_filled` line and the agent writes patch.txt at 77 and submits at 79. su-full r2 summary restates `[None, "numeric", "string"]` as an accomplishment. ss-partial r1 summary says "Files Modified: None" although sed edits ran at 32-36, and carries /tmp outputs from pip sklearn 1.9 as anchors; after comp the agent re-derives state from a 15-line view (85) and at 86/91 passes `fill_value` to `super().__init__()`.
3. Loss of failed-attempt history -> restore/reapply loops (all 9 limit runs). tr r3 re-issues the same non-matching sed after each compression (21,30,41 pre; 96,99,101,106,109 post-98) even though the real `"random_state": ["random_state"],` line was displayed at 15 and 105. otrc-su-partial r1 issues the identical destructive sed at 105 and 122 after its 105 result left the 4-output window. otrc-ss-partial r1 repeats the restore+script+4-grep cycle 10 times with the same failing docstring check (obs 104 == obs 124). trc r1 repeats `sed -i '118a\\n...'` 5 times, each time producing literal `\n` (obs 41,43,95).

With a 4-output window every file view is gone within 4 steps, so each edit is made against a fresh partial view and each verification against a stale belief.

## Root cause
The task is five mechanical hunks, but the container cannot run any sklearn code (wrong interpreter, never activated), so success is decided purely by whether the agent (a) reproduces the repo's constraint idiom (`"no_validation"`, or omits the entry) and (b) lands the edits without collateral damage and reviews one clean diff. FC keeps the `_base.py` read and the full record of which sed patterns failed and which restores happened; after one corruption it restores once, re-applies once via script, reads the diff and submits (3/3, edit phase ~25 steps). Compression removes exactly those two things: the constraint example (-> 5 patches with `"numeric"`/`"string"`/bare `None` that raise at `fit`) and the failed-edit history (-> restore/reapply loops of 4-10 restores, repeated non-matching or destructive seds, 9 step-limit runs, 3 of which discarded a correct patch already on disk). Summaries additionally certify completeness, so post-compression diffs that plainly show the defect (su-full r1@76, otrc r2@58, otrc-ss-partial r3@102, trc-su r3@92) are not acted on. Environment trap: pip-installed sklearn 1.9 (fill_value already present) yields false positive "verification" that SS-partial preserved into its summary.
