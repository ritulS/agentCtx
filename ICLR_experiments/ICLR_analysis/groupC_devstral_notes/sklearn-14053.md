## Gold fix & hidden constraints
- Bug: `export.py` L893 builds a **per-node** list `feature_names_ = [feature_names[i] for i in tree_.feature]`; leaves have `tree_.feature == -2` (TREE_UNDEFINED) so `feature_names[-2]` raises IndexError when `len(feature_names) < 2`. L931 `name = feature_names_[node]` is *correct* for a per-node list (it is guarded by `tree_.feature[node] != TREE_UNDEFINED`).
- Gold: keep the per-node list, guard the leaf entries (`feature_names[i] if i != _tree.TREE_UNDEFINED else None`). Any fix must keep the two sites **consistent**: either (A) per-node list + `[node]` (gold), or (B) per-feature list/dict + `[tree_.feature[node]]`. FC used B in all 3 runs; both A and B pass.
- Hidden test constraints: the new assertion uses a regressor with `feature_names=['first']`; the *existing* assertions in the same test call `export_text(clf)` **without** feature_names on a 2-feature tree and call it several times in a row. So a fix must (i) still work when `feature_names is None`, (ii) keep `export_text.report = ""` reset, (iii) give correct names on multi-feature trees.
- Plausible-but-wrong classes produced: **S-only** swap L931 -> `feature_names_[tree_.feature[node]]` with L893 untouched (still IndexError on the PR case); **C-only** per-feature list at L893 with `[node]` kept at L931; **F+S** filter -2 out of the per-node list + swap (wrong names / IndexError on multi-feature); **D** dict keyed by `tree_.feature` values (still evaluates `feature_names[-2]`); **G+S** gold-equivalent construction plus the swap (per-node list indexed by feature id); **N** index `feature_names` (may be None) directly at L931; **R** deleted `export_text.report = ""`.

## Mechanisms with evidence
1. **Single-site misread is model-native, compression freezes it.** The swap-only belief ("feature_names_ is indexed by feature index") is stated identically at ss-partial r2 s19, su-full r3 s30, trc r1 s22/25 and also in su-partial r1's summary (resolved) and FC r3 s24. What differs is whether L893 is edited too. After compression the belief is promoted to fact: ss-partial r2 summary "The bug has been fixed ... at line 931"; su-full r3 summary "Progress: Identified and fixed the bug ... at line 931" plus the false model of L893. None of the three ever displayed L893 again after the event; remaining 20-30 steps are mock tests derived from the summary.
2. **Summaries mis-state file state.** ss r1: "The fix has been applied" (msg 2) when step 37 had restored the original (confirmed by step 49 grep); the agent then re-applies exactly what the summary describes (L893-only). su-partial r1 (resolved): summary says "Modifications Made: None yet" although L893 was edited at 26-35; the post-summary swap at 42 then *completes* the pair by accident. Same false belief, opposite outcome, decided by what was already on disk.
3. **Anchors replay a wrong plan.** ss r2: SS summary quotes both wrong sed commands; after 40 steps of `\n`-corruption repair and a `git checkout` (85) the agent re-runs them (86, 108) and submits F+S. trc-su r2: `git checkout` at 47-48 silently reverted the swap; both edits re-applied from memory (50-58).
4. **TRC/OTRC remove the only correction channel.** trc r1 read L893 and L931 in separate outputs (17, 18); after clearing at 39 every later look is a grep for L931 only (48, 51, 57, 63). otrc-su-partial r2 reached the gold-equivalent L893 at 55 and then re-applied the swap at 57 because its own step-23 turn ("need to fix line 931") survives while observations do not.
5. **Not compression-caused (5 runs).** tr r1, trc-su r1, trc-ss r1, trc-ss r3, otrc-su-partial r2 made the decisive wrong edit with the relevant code in context (steps 28-42, 23-38, 40, 28-35, 57). Compression here only delayed nothing; these are sloppy edits (deleted report reset, `feature_names` vs `feature_names_`, dropped else-branch) that mock-based verification cannot catch.
6. **Resolved compressed runs vs failing.** 12/14 threshold-compressed resolved runs applied both edits as an adjacent pair before the first event (su-full r1 25/26, su-full r2 25/26, trc r2 18/19, trc r3 29-35, trc-su r3 28/29, tr r3 24-26, ss-partial r1 27-32, ss-partial r3 29-37, su-partial r2 25-30, su-partial r3 20-39, tr r2 23-31, trc-ss r2 42-45); ss r3 did both at 53/54 after re-viewing 890-940 at 49 post-summary. Resolved TR r2 and SU-full r2 are the only runs that reproduced gold's per-node+guard form.

## Root cause
The fix is a two-site invariant (L893 construction and L931 lookup must agree); the container cannot run any sklearn code (py3.11 vs cpython-36m extensions), so correctness depends entirely on the agent reading L890-935 as one unit. Devstral's dominant reading is that `feature_names_` is per-feature, which is only correct if L893 is rewritten at the same time; FC did so in all 3 runs immediately after a window showing both lines. Under compression the same reading is either applied to one site and then frozen by a summary that declares the bug fixed (SS/SU: ss-partial r2, su-full r3, ss r1) or the file views are cleared so only L931 is ever re-inspected (TRC: trc r1), and the remaining budget is spent on tautological mock tests; summaries also mis-report file state (ss r1, su-partial r1) and replay wrong sed anchors after `git checkout` (ss r2, trc-su r2). The other 5 failures are edit slips made with the code in view that no policy could have caught without a runnable test.
