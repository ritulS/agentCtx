## Root cause
The task's two-line fix is easy to find but the container makes verification expensive: `python` is the 3.11 base interpreter, so every run first burns 10-45 steps hacking `collections.abc` imports into sympy core files, and those hacks are poison if submitted (4 P2P DeprecationWarning exceptions in the 3.9 eval env). FC succeeds because it keeps two long-range facts intact — which lines were fixed and which files were env hacks — and reaches `git diff -- sympy/printing/str.py`. Compression breaks the run in three ways with different signatures: full summaries (SS/SU-full) make Devstral restart exploration from scratch (ss r3 twice) or hand it an agenda of extra methods to audit (su-full r1) so it never submits; truncation and TRC lose the "edit already applied" state, causing re-edits, a `git checkout` revert and a two-step-short finish (tr r3), or drop the "these are env hacks" provenance so the agent diffs all five files (su-partial r3, trc-ss r1, trc-su r3); online clearing with a 5-observation window lets a wrong first hypothesis (`_print_Eq`) persist for 60+ steps (otrc-tr r3, otrc r1) or degenerate into identical-command loops (otrc-ss-partial r3). The common denominator on this task is not a lost file read but lost *provenance and completion state* plus the model's tendency to keep auditing str.py instead of submitting: 10 of 15 timed-out runs ended with the correct fix on disk and no patch.
