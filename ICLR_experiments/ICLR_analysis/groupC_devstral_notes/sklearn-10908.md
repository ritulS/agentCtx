# sklearn-10908 (scikit-learn__scikit-learn-10908) — Devstral-24B, ICLR_experiments/swebench/main/devstral24b

Outcome: FC 3/3 resolved. Compressed 36 runs: 15 resolved, 12 submitted-unresolved, 9 step-limit (7 of the 9 are the OTRC harness bug).

## Gold fix & hidden constraints
- Gold: in `CountVectorizer.get_feature_names()` add `if not hasattr(self,'vocabulary_'): self._validate_vocabulary()` before `self._check_vocabulary()` (text.py ~L996). This is a verbatim copy of the guard already present in `transform()` (L953-954).
- Hidden constraint (test patch only, invisible to agent): `test_feature_names` adds `assert_false(cv.fixed_vocabulary_)` right after `assert_raises(ValueError, cv.get_feature_names)` on an *unfitted, no-vocabulary* CV, and `assert_true(cv.fixed_vocabulary_)` after the custom-vocab call. `fixed_vocabulary_` is only set inside `_validate_vocabulary()` (else-branch sets False). Therefore any fix that calls `_validate_vocabulary()` only when `self.vocabulary is not None`, or that bypasses inside `_check_vocabulary()`, raises AttributeError on `fixed_vocabulary_` and fails.
- Plausible-but-wrong classes actually produced: **B** = gold guard plus `and self.vocabulary is not None` (4 runs); **C** = rewrite `_check_vocabulary()` to accept/validate the `vocabulary` param (5 runs + 2 limit runs); **E** = replace `_check_vocabulary()` by `_validate_vocabulary()` in get_feature_names (unfitted case no longer raises; 1 run); **A'** = unconditional `self._validate_vocabulary()` before `_check_vocabulary()` in get_feature_names only — passes (5 resolved runs). A'x3 (also in transform/inverse_transform, trc-su r1) breaks PASS_TO_PASS `test_countvectorizer_custom_vocabulary` (`typ=iter`: second `_validate_vocabulary()` in `transform` re-iterates an exhausted iterator -> "empty vocabulary").

## Environment (same trap in all 39 runs)
- `python` = /opt/miniconda3 Python 3.11.5; the built `sklearn/__check_build/_check_build.cpython-36m-*.so` is for 3.6. Every import of sklearn from /testbed dies with `ModuleNotFoundError: sklearn.__check_build._check_build` (seen 2-13x per run). `python setup.py build_ext --inplace` fails (Cython/py3.11), pytest is not installed (`No module named pytest`, 20 runs). No run ever found a 3.6 interpreter.
- Consequence: no run can execute the real test; every run "verifies" with hand-written mock classes that re-implement the agent's own logic (e.g. tr r1 step 48 MockCountVectorizer). Verification is therefore tautological in FC and compressed runs alike; syntax errors are also undetectable this way (su-partial r2/r3).
- Misleading side-paths: `pip install scikit-learn` (ss-partial r1 step 23; ss r3 step 20; trc-su r1 steps 29,49) installs sklearn 1.9 into py3.11; ss-partial r1 step 27 then ran its script from /tmp against 1.9 and saw `AttributeError: no attribute 'get_feature_names'`, which it misread ("installed version doesn't have the method", step 28).

## Mechanisms with evidence
1. **Decisive information = the transform() guard idiom.** Runs with `if not hasattr(self, 'vocabulary_'):` (L953) in context at first-edit time: 16/16 produced A/A' (all 3 FC + 13 compressed). Runs without it in context at first edit: 3/16 A/A' (su-full r3, trc-ss r3; otrc-su-partial r1 only after re-reading it at 54/60 and re-editing at 65/69), 13/16 wrong (B/C/E/limit). In 10 of those 13 the agent simply never read transform before editing (exploration variance, not compression: ss r3, ss-partial r1, su-partial r3, tr r1, trc r1, trc-su r2, otrc-su-partial r2/r3, trc-ss r3-ok, su-full r3-ok). In OTRC runs the 5-step clearing window (token_log `flag_from_step = step-5`) guarantees anything read >4 steps earlier is gone: otrc-su-partial r3 read `_validate_vocabulary` at 15-16, edited at 29-30; otrc-tr r1 read it at 11, first edit 36.
2. **Wrong class is chosen before the first threshold compression in 8/9 threshold-policy failures** (ss r3 38<43, ss-partial r1 34<39, su-partial r2 35<48, su-partial r3 31<45, tr r1 31<40, trc r1 32<40, trc r2 23<43, trc-su r2 29<39). Compression did not cause the choice; it removed the raw pre-edit reads, after which every run (FC included) only ran self-confirming mock tests and submitted. Only trc-su r1 (first compression 32 < first edit 37) shows post-compression edit-state loss: 5 summaries -> reapply/checkout/restore cycle (steps 41,42,78-92) -> global sed hitting 3 call sites.
3. **Post-summary restart loops (SS full)**: ss r2 restarted from `find`/`cat`/`grep class CountVectorizer` after each of 3 summaries (steps 15-25, 63-72, 103-112; 4,5,1 exactly-repeated commands in the following 15 steps) and hit the limit with an unsubmitted C edit (`git diff` count 0). Resolved SS/SU runs with 2 events also ran ~100 steps (ss r1 102, ss-partial r2 101, su-partial r1 102) versus FC 54-77.
4. **OTRC re-implementation loop**: otrc-tr r1 wrote `_check_vocabulary` 11 times via /tmp/fix_vocabularyN.py; each mock-test run (53,55,57,59,65,76,79,81,91,93,96) exposed a new bug in its own vocab parsing (thoughts at 49,61,70,77,92: "I see the issue - ..."); final method at step 122 re-implements dict/iterable conversion instead of calling `_validate_vocabulary()`; never reached `git diff`.
5. **Summary launders a broken edit** (weak): su-partial r2/r3 summaries (msg[2]) quote the edited method with a well-formed `"""` docstring while the file has `name"` / `name""/` (steps 36/50 and 32/47 show the raw broken line; agent did not notice either time). FC r3 hit the same sed-garbling at step 23 and repaired it at 25-28 while the garbled view was still in context.
6. **Environment blindness amplifies everything**: with imports impossible (3.6 .so vs 3.11 python) no run could run `test_feature_names`, so B/C/E and the syntax errors were never caught; `pip install scikit-learn` created a false negative at ss-partial r1 step 27.

## Root cause
FC resolves 3/3 because each FC run had read `transform()` (L932-980) before editing and copied its `if not hasattr(self,'vocabulary_'): self._validate_vocabulary()` guard, which by construction sets `fixed_vocabulary_` and satisfies the hidden `assert_false(cv.fixed_vocabulary_)`. Among compressed runs the same rule holds (16/16 with the guard in context -> pass; 13/16 without -> B/C/E variants that never set `fixed_vocabulary_`), but for this task most of the missing-guard cases are exploration variance that precedes the first compression event, plus 7 runs lost to the OTRC messages[1] harness bug. Genuine compression mechanisms are confined to: OTRC's 5-step window forcing re-implementation instead of reuse (otrc-tr r1, otrc-su-partial r3), SS restart-exploration loops (ss r2), and multi-event edit churn ending in an over-broad sed (trc-su r1). Because the container cannot import sklearn (py3.11 vs 3.6 .so), no run could detect a wrong variant, so whichever guard the agent first wrote was submitted.
