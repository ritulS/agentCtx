# sympy__sympy-13757 — Devstral-Small-24B, ICLR_experiments/swebench/main/devstral24b

## Gold fix & hidden constraints
- Gold: one line in `sympy/polys/polytools.py`, class `Poly`: `_op_priority = 10.001` (any value > 10.0 works; runs used 10.1/11.0/20.0 and resolved).
- Mechanism: `x*Poly(x)` calls `Expr.__mul__` (Symbol has no own `__mul__`), decorated `@call_highest_priority('__rmul__')`; the decorator only defers to `other.__rmul__` when `other._op_priority > self._op_priority`. Poly inherits 10.0 == Symbol's 10.0, so `Poly.__rmul__` is never reached. Traceback-free bug: the PR shows only REPL output, and the obvious-looking target (`Poly.__rmul__`, lines 4051-4058) is a red herring — any edit there is dead code.
- Hidden constraints (PASS_TO_PASS): `Poly(x,x)*2` (needs `@_sympifyit` on `__mul__` intact), `Poly(1,x)+sin(x)` (exercises the `except PolynomialError` fallback), `x*oo`, `(-I*x*oo).match(...)` (global `Expr.__mul__` must not delegate blindly). Any extra hunk in `__mul__/__rmul__`, `expr.py` or `decorators.py` is the failure surface.
- Wrong-but-plausible fixes invited: swap `g*f.as_expr()`->`f.as_expr()*g` / `g.mul(f)`->`f.mul(g)` in `__rmul__` (no-op), widen `except PolynomialError`, change `call_highest_priority` `>` to `>=`, add delegation in `Expr.__mul__`, edit `Mul.flatten`.

## Root cause
The task is a one-line fix whose location is only reachable by a three-hop inference (Expr.__mul__ -> call_highest_priority -> equal _op_priority) that the model must hold in context simultaneously, preceded by a 5-21-step Python-3.11 environment detour that consumes roughly half the 21k budget before investigation starts; the PR's REPL-only description points at `Poly.__rmul__`, a dead-code decoy that invites speculative edits. FC succeeds (2/3) because once the priority probe is done (steps 45-57) the edit, its verification, and the knowledge that earlier speculative edits and env fixes are not part of the fix stay visible through submission. Compression fails this task in three ways: (i) tool-result clearing (TRC/OTRC) erases the "edit already applied / verified" state and the evidence that earlier hunks were speculative, producing duplicate inserts, re-done work, and patches where the correct line is shipped alongside a fatal extra hunk (trc r3, otrc r3: gold line present, `NameError`/`AttributeError` in P2P); (ii) summaries preserve the agent's wrong plan as fact, so a run that was already off-course keeps rewriting `decorators.py` after each summary (ss-partial r3); (iii) per-step online clearing breaks the multi-file inference chain entirely, so 4 of 11 non-bug online runs never see `_op_priority` and burn the step budget re-reading the same lines and rewriting `__rmul__`/`Mul`. Threshold policies still resolve 19/24 because compression usually fires after the edit (step 55-91) and only the verification tail is degraded.
